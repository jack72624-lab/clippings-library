MCP vs API：執行層，與該不該用的四個問題

可波 AI 白話（彙整 Google Cloud Tech ＋ IBM Technology）· YouTube 原片 ↗
簡報 · In Brief核心 5 點
  1. 01

    模型不會執行 API：模型只是產生一個「請呼叫某某工具」的請求，真正拿著它去打 API 的是模型旁邊那層程式，那層叫執行層。它握著金鑰、負責重試、負責擋下不該做的動作。

  2. 02

    MCP 是疊在 API 上面，不是取代：你的後端一行都不用動。MCP 取代的是模型跟 API 之間那層翻譯程式。所以「MCP vs API」這題本身就問錯了，兩者不在同一層。

  3. 03

    它做的實際上是三件事：抽象化（把 API 轉成模型讀得懂的格式）、認證、限定權限。中間那個最常被跳過，卻是三個裡面最重要的。

  4. 04

    價值是一道算術題：把乘法變加法。兩個應用乘十個服務等於二十份整合程式碼；換成 MCP 是二加十。真正的差別在第三個應用進來時，它直接重用那十台 server。

  5. 05

    三種情況不要用：確定性流程、一次性任務或只有一個應用、沒有現成的 server。只有一個應用只接兩三個服務，那個乘法根本不會爆炸，MCP 對你就是純成本。

一句話

MCP 沒有讓模型變強，它只是讓多個應用共用同一層執行層，而不是各蓋各的。

Impeccable 4.0：live mode 與 177 個風格方向

Chase AI · YouTube 原片 ↗
能力 · Pattern要點 3 條
  1. 01

    真正的資訊是版本落差：這支 skill 本來就已經裝著，裝的是 3.9.1，影片講的是 4.0。所以這則的價值不是「認識一個新工具」，是「你落後了一版，而落後的那版新增的東西剛好會用到」。

  2. 02

    4.0 新增兩塊：live mode（在瀏覽器裡直接點選頁面元件、下指令產生多個變體、每個變體還能再微調，滿意才回寫）；以及一批現成的風格方向，讓第一步從「憑空描述」變成「看圖挑一個再往下走」。

  3. 03

    兩個值得吸收的心法：一是別再期待一次到位，設計本來就是迭代的；二是通用型工具與一招流工具的取捨，一招流每次都給你一個好看的結果但只會做那一種，通用型下限低、更吃你自己的判斷，天花板卻高很多。

一句話

工具功能會改版、筆記會過期；這則的正確產出是一個升級動作，不是一則知識。
